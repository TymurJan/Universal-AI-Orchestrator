# Talan Core Skill

Цей скіл налаштовує роботу Агента в рамках екосистеми ГО "Талан ЮА". **Правила цього скіла є універсальними та діють у всіх сесіях незалежно від профілю входу.**

> 🔴 **МОВА ВИВОДУ (АБСОЛЮТНИЙ ПРІОРИТЕТ):** Агент ЗОБОВ'ЯЗАНИЙ формувати плани виконання, артефакти, списки завдань та всі відповіді **виключно українською мовою**. Правило, чек-лист та few-shot приклади визначені в `artificial-soul-profile/SKILL.md` — вони є обов'язковими для виконання. Використання англійської мови у планах та відповідях є **КРИТИЧНОЮ ПОМИЛКОЮ**.

## 1. Специфіка Організації та Проєктів

- **Основна сутність:** ГО «Талан ЮА»
- **Ключовий проєкт:** Проєкт «Ашрам» (ПТСР-реабілітація).
- При роботі та спілкуванні з документацією Агент захищає інтереси організації та керується принципами безпеки.

## 2. Логотип та брендинг

- **Основний еталон:** `d:\ГО Талан UA\Установчі документи\image1.png` (верхній ряд, крайній правий) — для всіх офіційних документів.

## 6. 🔥 ПРОТОКОЛ "ЖОДНИХ СКОРОЧЕНЬ" (NO SHORTENING HARDENING)

> ⚠️ **СИСТЕМНЕ ОБМЕЖЕННЯ:** Цей протокол ПОВНІСТЮ ВИМИКАЄ внутрішні алгоритми узагальнення (Summarization Bias) для всіх робочих файлів проекту.

1. **Технічна заборона маркерів:** Агенту суворо ЗАБОРОНЕНО використовувати символи `...`, `(без змін)`, `(решта тексту аналогічно)` або будь-які інші замінники контенту.
2. **Цілісність даних (Data Integrity):** При зміні файлів `.md, .py, .js, .json, .docx` Агент ЗОБОВ'ЯЗАНИЙ переносити 100% тексту.
3. **Технічний Контроль (Integrity Guard):** Після кожної зміни плану (`.md`) або коду (`.py`), Агент **ЗОБОВ'ЯЗАНИЙ** запустити перевірку:
   ```powershell
   python talan/autobot/integrity_guard.py <шлях_до_файла>
   ```
   Якщо скрипт видає помилку — операція вважається ПРОВАЛЕНОЮ, і Агент має переписати файл повністю. Жодні виправдання не приймаються.
4. **Семантична Цілісність (Semantic Integrity):** Агенту суворо ЗАБОРОНЯЄТЬСЯ спрощувати, узагальнювати чи "стискати" складні методології та правила під час рефакторингу документів або написання промптів. Агент зобов'язаний зберігати максимальну семантичну щільність директив користувача. Глобальне розуміння контексту зникає між сесіями, тому всі ключові інструкції мають залишатися дослівно деталізованими.
5. **Виняток:** Лаконічність дозволена **ТІЛЬКИ У ЧАТІ**. Документація та правила = повна деталізація.

## 7. 🛡️ TALAN SHIELD PROTOCOL (ANTI-DDOS ТА ЗАХИСТ ДАНИХ)

> ⚠️ **СИСТЕМНЕ ОБМЕЖЕННЯ:** Будь-який веб-додаток, портал або бот, який Агент створює або модифікує для ГО "Талан ЮА", повинен за замовчуванням містити архітектуру "Подвійних вхідних дверей" (Defense in Depth).

1. **Зовнішні двері (Edge Protection):** Усі веб-додатки (Frontend/Backend) проєктуються для роботи за екраном **Cloudflare**. Це автоматично блокує DDoS атаки на мережевому рівні та зберігає Always Online кеш при падінні бекенду.
2. **Внутрішні двері (Rate Limiting & Throttling):** Всі API та Telegram-боти ПОВИННІ мати вбудований Throttling Middleware. Жоден клієнт не має права надсилати більше 1-2 запитів на секунду. Бот зобов'язаний ігнорувати спам-шторми (Double Front Door effect).
3. **Захист Бази Даних (Concurrency Control):** Агенту суворо ЗАБОРОНЕНО писати дані напряму в файли (`json.dump` чи `csv.write`) без використання Асинхронних Замків (`asyncio.Lock()`), `aiofiles` або транзакцій. Race Conditions недопустимі.

## 8. 💡 ПРОТОКОЛ ОПТИМІЗАЦІЇ КОНТЕКСТУ ТА ЕКОНОМІЇ КВОТ (CONTEXT & QUOTA OPTIMIZATION)

> ⚠️ **СИСТЕМНЕ ПРАВИЛО:** Агент зобов'язаний мінімізувати навантаження на контекст (Context Overhead) для збереження хмарних квот.

1. **Заборона автоматичного перечитування великої документації:** Агенту суворо ЗАБОРОНЕНО за власною ініціативою зчитувати великі файли архітектури (як-от `ECOSYSTEM_ARCHITECTURE.md`), тексти грантових заявок (`IREX_Grant_Proposal_NovyShlyakh.md`) або Excel-таблиці повністю при виконанні точкових технічних завдань (правка окремої функції, виправлення синтаксису). Зчитування великих документів дозволяється виключно за прямим запитом користувача або при зміні глобальної архітектури.
2. **Локальна семантична пам'ять (RAG):** Для отримання історичного контексту розробки, попередніх рішень або деталей гранту Агент зобов'язаний спочатку скористатися векторним пошуком через локальну базу ChromaDB (`python Universal-AI-Orchestrator/tools/memory_tool.py query "запит"`) замість повного перечитування великих логів чи файлів.
3. **Універсальний Журнал Стану (Ecosystem State Ledger):** Фінансові, статусний та технічний аудити проводяться виключно за рахунок єдиного агрегованого файлу `ecosystem_state_ledger.json` (або `data/finance.json`), куди всі підпроєкти (AG, NS, UO) локально записують свої транзакції, статус версій та критичні події. Агенту заборонено самостійно сканувати вихідні коди та логи окремих підпроєктів для збору цієї статистики.
4. **Контроль та Моніторинг оновлень (Watchdog):** Агент зобов'язаний автономно аналізувати оновлення та критичні зміни логіки/версій коду за допомогою локального скрипту `talan/autobot/meta_optimizer.py`. У разі виявлення відкатів, помилок у логах або розбіжностей у capabilities, Агент зобов'язаний не проводити мовчазні зміни коду, а сформувати структурований звіт в Артефактах із запропонованим планом дій та чекати згоди користувача.
