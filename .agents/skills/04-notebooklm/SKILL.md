# NotebookLM Integration Skill

## Опис
Цей скіл описує логіку взаємодії агента з системою локальних "блокнотів", що імітують функціонал NotebookLM за допомогою GPT-4o та файлової системи. Всі блокноти зберігаються в локальній директорії бази знань проекту.

## Структура Блокнотів
- Основна директорія: `Knowledge_Base/02_Service_Activity_Partnerships/` (або корінь `Knowledge_Base`).
- Формат файлу: `.md` (Markdown).

### Шаблон створення нового блокнота
При створенні нового блокнота або теми, агент має використовувати GPT-4o (з роллю "менеджер-проєктів NGO") для генерації структури з наступними обов'язковими розділами:
```markdown
# [Назва Теми]

## Мета

## Контекст

## Ключові факти

## Контакти

## Наступні кроки

## Нотатки
```

## Правила роботи та збереження інформації (Нотаток)
- Нотатки або записи зберігаються у файл `Notes.md` всередині папки відповідної категорії (наприклад, `Knowledge_Base/99_[Назва_Категорії]/Notes.md`).
- Перед збереженням нової нотатки, текст має бути відформатований та структурований через GPT-4o з роллю "редактор" (очищення від шуму, додавання маркерів та структури, без вигадок).
- Формат запису:
```markdown
---
### 📝 Запис від [YYYY-MM-DD HH:MM]

[Структурований текст нотатки]
```

## Інтеграція з Telegram Ботом (bot.py)
У боті ця логіка реалізована через наступні команди:
- `/блокнот <назва>` — генерація структури та створення файлу блокноту за шаблоном.
- `/записати <категорія> | <текст>` — форматування тексту та збереження у `Notes.md` відповідної категорії.
- `/базазнань` — перегляд існуючої структури блокнотів.

## Вимоги до Агента
Агент повинен самостійно притримуватись цього формату при роботі з завданнями, пов'язаними з генерацією документації, створенням нових тем чи поповненням бази знань організації через файлову систему або Telegram бота.
