# Програма курсу: Кібербезпека з нуля та захист даних ГО

Ласкаво просимо до навчальної програми **Talan Academy**. Цей курс розроблено спеціально для того, щоб підготувати команду ГО «Талан ЮА» до побудови надійних, безпечних та комплаєнтних систем захисту персональних даних та цифрових сервісів. 

Програма складається з **5 концептуальних модулів** та охоплює **25 практичних уроків**. Кожен урок включає теоретичну базу, приклад реального застосування в екосистемі ГО та практичне домашнє завдання для самостійного виконання в IDE.

---

## 📂 Модуль 1: Комп'ютерні мережі та хмарна безпека (Cloud Security)
*Цей модуль закладає технічний фундамент: як працюють мережі, сервери та як захистити наш хостинг VPS.*

### Урок 1: Вступ до комп'ютерних мереж: IP-адреси, порти та протоколи TCP/UDP
- **Теорія:** Поняття мережевих пакетів, різниця між надійним TCP та швидким UDP протоколами. Як працює маршрутизація та DNS.
- **Практика для ГО:** Розуміння мережевої адресації нашого сервера.
- **ДЗ:** Написати скрипт для перевірки доступності IP-адреси сервера (ping-тест) та сканування базових відкритих портів.

### Урок 2: Веб-протоколи: HTTP/HTTPS та TLS/SSL шифрування в дорозі (Transit)
- **Теорія:** Як працює незахищений протокол HTTP та чому HTTPS є обов'язковим для збору чутливих даних ветеранів.
- **Практика для ГО:** Налаштування SSL-сертифікатів (Let's Encrypt) на порталі «Новий Шлях».
- **ДЗ:** Написати скрипт, який робить безпечний HTTPS-запит до API та валідує статус SSL-сертифіката цільового сайту.

### Урок 3: Безпека хмарної інфраструктури: Налаштування VPS та фаєрволів (UFW)
- **Теорія:** Що таке віртуальний сервер (VPS), чому хмара є публічним простором та як налаштувати базовий брандмауер.
- **Практика для ГО:** Конфігурація правил доступу до бази даних порталу.
- **ДЗ:** Створити скрипт автоматичного аудиту правил фаєрволу UFW та виведення списку дозволених IP-адрес.

### Урок 4: Керування портами та моніторинг трафіку на хостингу: Інструменти Nmap та Netstat
- **Теорія:** Визначення закритих, відкритих та фільтрованих портів. Чому зайві відкриті порти — це вразливість.
- **Практика для ГО:** Сканування хостингу порталу на предмет небажаних служб.
- **ДЗ:** Написати Python-скрипт, який викликає утиліту `netstat`/`ss` та сигналізує про нові невідомі мережеві підключення.

### Урок 5: Безпечний віддалений доступ: SSH-ключі та захист від брутфорсу (Fail2ban)
- **Теорія:** Чому авторизація за паролем по SSH є небезпечною. Принцип роботи асиметричних ключів.
- **Практика для ГО:** Закриття доступу до консолі сервера за паролем, переведення на ключі.
- **ДЗ:** Створити парсер логів `/var/log/auth.log` для виявлення та підрахунку невдалих спроб SSH-авторизації.

## 📂 Модуль 2: Захист персональних даних та стандарти комплаєнсу (Compliance)
*Модуль присвячений правовим вимогам, міжнародним донорам та юридичній чистоті збереження чутливих даних.*

### Урок 6: Стандарт GDPR: Захист персональних даних ветеранів та принципи Privacy by Design
- **Теорія:** Сім ключових принципів європейського регламенту GDPR. Чому безпеку даних треба проектувати від початку.
- **Практика для ГО:** Проектування бази даних ветеранів з урахуванням мінімізації полів.
- **ДЗ:** Написати скрипт для симетричного шифрування персональних полів за алгоритмом Fernet (AES-256).

### Урок 7: GDPR на практиці: Впровадження згоди (Consent) та права на забуття (Right to be Forgotten)
- **Теорія:** Правила збору згоди користувачів. Як реалізувати технічне видалення без порушення реляційної цілісності бази даних.
- **Практика для ГО:** Функція самовидалення профілю ветерана з бази порталу «Новий Шлях».
- **ДЗ:** Написати скрипт повного видалення та знеособлення (анонімізації) записів профілю ветерана в тестовій базі SQLite.

### Урок 8: Стандарт PCI DSS: Безпека фінансових транзакцій при зборі донатів
- **Теорія:** Стандарти безпеки платіжних систем. Чому ГО заборонено зберігати номери карт донорів на своїх серверах.
- **Практика для ГО:** Безпечна інтеграція платіжних віджетів (LiqPay, Stripe).
- **ДЗ:** Створити скрипт валідації вхідних даних транзакцій (webhook) платіжного шлюзу за допомогою цифрового підпису SHA-256.

### Урок 9: Стандарт Privacy Shield та транскордонна передача даних
- **Теорія:** Правила передачі даних за межі ЄС/України. Безпека використання хмарних сховищ (Google Drive, AWS).
- **Практика для ГО:** Налаштування локації зберігання резервних копій у хмарах.
- **ДЗ:** Скрипт перевірки конфігурації сховища S3 на предмет відсутності публічного доступу (public read/write).

### Урок 10: Етичні та правові аспекти інформаційного захисту соціальних проектів
- **Теорія:** Межа між безпекою та зручністю ветерана. Делікатність збереження медичних даних та діагнозів (ПТСР).
- **Практика для ГО:** Розділення рівнів доступу для волонтерів, психологів та адміністраторів.
- **ДЗ:** Створити систему перевірки ролей (RBAC) на Python для розмежування доступу до чутливих текстових полів.

## 📂 Модуль 3: Веб-вразливості та розробка DevSecOps
*Вивчення методів атак (Red Team) та побудова безперервного автоматичного захисту коду (Blue Team).*

### Урок 11: Основні вразливості веб-додатків (OWASP Top 10): SQL-ін'єкції та XSS-атаки
- **Теорія:** Як зловмисники впроваджують шкідливий код у форми вводу на сайтах та викрадають дані.
- **Практика для ГО:** Захист пошукової форми на порталі від SQL-ін'єкцій.
- **ДЗ:** Написати скрипт очищення (санітизації) HTML-вводу для запобігання XSS-атакам у коментарях.

### Урок 12: Безпека коду (DevSecOps): Автоматичний статичний аналіз коду (SAST) в CI/CD
- **Теорія:** Що таке безпечна розробка. Інтеграція автоматичних сканерів безпеки на етапі написання коду.
- **Практика для ГО:** Налаштування лінтерів безпеки в репозиторії.
- **ДЗ:** Інтегрувати сканер `Bandit` для пошуку вразливостей у Python-коді та запустити його аудит локально.

### Урок 13: Стратегія захисту Blue Team: Налаштування логування та аудит дій
- **Теорія:** Якщо подія не залогована — її не було. Що таке аудит-лог та чому адміністратор не має права видаляти власні логи.
- **Практика для ГО:** Налаштування безпечного логування в Telegram-боті ГО.
- **ДЗ:** Створити захищений асинхронний логер, який записує критичні дії користувачів та дублює їх в окремий файл із міткою часу.

### Урок 14: Методологія атак Red Team: Тестування на проникнення (Penetration Testing)
- **Теорія:** Як етичні хакери шукають слабкі місця у системі. Фази розвідки, сканування та експлуатації дір.
- **Практика для ГО:** Самостійний пошук відкритих файлів конфігурації.
- **ДЗ:** Написати скрипт, який сканує тестову структуру проекту на наявність випадково забутих конфіденційних файлів (наприклад, `.env.backup`, `secrets.json`).

### Урок 15: Керування залежностями: Сканування бібліотек на вразливості (Pip-audit)
- **Теорія:** Вразливості нульового дня (Zero-day) у сторонніх пакетах. Чому застаріла бібліотека — це відкриті двері для хакерів.
- **Практика для ГО:** Регулярне оновлення модулів екосистеми.
- **ДЗ:** Написати автоматичний скрипт, який використовує `pip-audit` для аналізу `requirements.txt` і надсилає сповіщення у разі знаходження критичних застарілих версій.

## 📂 Модуль 4: Безперервність бізнесу та реагування на інциденти (Resilience)
*Як пережити кібератаки, технічні збої та блекаути без втрати критичної бази даних.*

### Урок 16: Розробка плану безперервності процесів (Business Continuity Planning — BCP)
- **Теорія:** Аналіз впливу на бізнес (BIA). Визначення RTO (допустимий час простою) та RPO (допустима втрата даних).
- **Практика для ГО:** Розробка регламентів роботи команди при відключенні основного сервера.
- **ДЗ:** Описати текстову матрицю ризиків для ГО «Талан ЮА» та створити скрипт розрахунку RTO/RPO для сервісів.

### Урок 17: Реагування на кіберинциденти (Incident Response) та стримування загроз
- **Теорія:** Шість кроків Incident Response: Підготовка, Ідентифікація, Стримування, Виправлення, Відновлення, Висновки.
- **Практика для ГО:** Створення інструкції для адміністраторів у разі злому бази даних.
- **ДЗ:** Створити скрипт "екстреної ізоляції" (Kill Switch), який при виявленні атаки миттєво відключає з'єднання з базою даних та блокує всі сесії.

### Урок 18: Резервне копіювання: Автоматизація бекапів та перевірка відновлення
- **Теорія:** Правило резервного копіювання "3-2-1" (3 копії, 2 типи носіїв, 1 віддалене сховище).
- **Практика для ГО:** Модернізація нашого скрипту `backup_manager.py` для синхронізації на зовнішній накопичувач E:.
- **ДЗ:** Написати автоматизований тест розпакування останнього бекапу SQLite та валідації цілісності даних у ньому.

### Урок 19: Робота в кризових ситуаціях: Протокол захисту конфіденційних даних ГО
- **Теорія:** Що робити, якщо пристрій співробітника захоплено фізично. Двоетапне шифрування дисків.
- **Практика для ГО:** Інструкція з активації Black Swan Protocol.
- **ДЗ:** Написати скрипт, який шифрує директорію з конфіденційними Excel-звітами за паролем і видаляє оригінали без можливості простого відновлення.

### Урок 20: Системи SIEM та SOC: Побудова центру моніторингу безпеки
- **Теорія:** Що таке Security Operations Center та SIEM (Security Information and Event Management) системи.
- **Практика для ГО:** Збір та аналіз логів з багатьох підсистем в єдиному місці.
- **ДЗ:** Створити скрипт агрегації логів із файлів `bot_log.txt` та `backup_log.txt` в єдиний структурований JSON для подальшого аналізу.

## 📂 Модуль 5: Штучний інтелект та безпека даних (AI & Data Quality)
*Сучасний рівень кіберзахисту: використання ШІ для аналізу загроз, виявлення аномалій та контроль якості даних.*

### Урок 21: Використання моделей машинного навчання для виявлення аномалій у трафіку
- **Теорія:** Як моделі ШІ допомагають виявити нетипову поведінку користувачів, яку не можуть зловити класичні правила.
- **Практика для ГО:** Моніторинг нетипово активних сесій у боті.
- **ДЗ:** Написати простий математичний алгоритм (на основі стандартного відхилення), який аналізує частоту запитів користувачів та сигналізує про аномальні сплески (DDoS-спам).

### Урок 22: ШІ проти шахрайства (Fraud Detection) при зборі допомоги
- **Теорія:** Які патерни поведінки характерні для шахраїв при спробі отримати гуманітарну чи фінансову допомогу.
- **Практика для ГО:** Попередній аналіз анкет заявок на гранти чи допомогу.
- **ДЗ:** Створити скрипт на Python, який аналізує текстові заявки на наявність маркерів копіювання згенерованого спаму чи повторюваних контактних даних.

### Урок 23: Безпека самих алгоритмів ШІ: Захист від отруєння даних (Data Poisoning)
- **Теорія:** Як зловмисники можуть обдурити моделі штучного інтелекту, підсовуючи їм хибні навчальні дані.
- **Практика для ГО:** Контроль якості вхідного RAG-контексту для нашого AI-оркестратора.
- **ДЗ:** Написати скрипт фільтрації RAG-джерел, який перевіряє текстові файли на наявність підозрілих шкідливих інструкцій (Prompt Injection).

### Урок 24: Етичні норми та якість даних (Data Quality) в системах прийняття рішень
- **Теорія:** Чому ШІ може бути упередженим (AI Bias). Контроль за тим, щоб алгоритми не дискримінували користувачів.
- **Практика для ГО:** Аудит відповідей AI-помічника.
- **ДЗ:** Створити скрипт валідації текстових відповідей ШІ-агента на відповідність етичним нормам організації (відсутність агресії, токсичності).

### Урок 25: Побудова комплексної системи безпеки на основі алгоритмів AI
- **Теорія:** Поєднання мережевого захисту, комплаєнсу, автоматизованого моніторингу та ШІ в єдиний захисний контур.
- **Практика для ГО:** Фінальна збірка та аудит безпеки всього нашого проекту.
- **ДЗ:** Створити інтегрований дашборд-скрипт, який збирає статус бази даних, логи безпеки, аналізує за допомогою ШІ поточний рівень загрози та виводить фінальний статус здоров'я екосистеми.
