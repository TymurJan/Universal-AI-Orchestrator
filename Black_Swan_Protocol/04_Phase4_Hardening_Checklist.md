# Фаза 4: Контрольний список інституційного зміцнення
**Організація:** ГО "ТАЛАН ЮА"
**Програма:** «Ашрам» — ХАБ реінтеграції з урахуванням ПТСР
**Класифікація:** Екстремальна стійкість (Інституційна)

*Цей контрольний список необхідно виконувати поступово, щоб перетворити ГО "ТАЛАН ЮА" на надзвичайно стійку структуру. Перевіряти щокварталу.*

## 1. Фінансове та юридичне зміцнення
- [ ] Відкрити вторинні та третинні банківські рахунки для бізнесу.
- [ ] Відокремити операційні кошти програми «Ашрам» від загальних адміністративних коштів.
- [ ] Створити та наповнити ізольований "Фонд виживання" (мінімум на 3 місяці накладних витрат).
- [ ] Сформувати цифрове сховище "Чиста кімната" (Установчі документи, Податки, Грантові угоди).
- [ ] Переконатися, що кожне минуле важливе рішення має цифровий підпис (Дія/КЕП) у Сховищі рішень Правління.
- [ ] Зібрати підписані Декларації про конфлікт інтересів (COI) від 100% членів основної команди та Правління.
- [ ] Підготувати ZIP-архів "Готовність до юридичного захисту".
- [ ] Визначити та провести попередні переговори щонайменше з одним зовнішнім кризовим юристом/юристом для ГО.

## 2. Управління та правонаступництво
- [ ] Розробити та офіційно підписати Протокол правонаступництва Засновника/Директора.
- [ ] Чітко визначити, що саме запускає надзвичайний стан за "Кодом Чорним".
- [ ] Чітко визначити, що саме запускає підвищення особи до статусу Виконуючого обов'язки (В.о.) Директора.
- [ ] Створити канал для асинхронного екстреного голосування Правління (наприклад, виділена верифікована група в Signal).
- [ ] Скласти матрицю Лімітів делегування повноважень (DoA).

## 3. Кібербезпека та конфіденційність даних (Фокус: «Ашрам»)
- [ ] Провести аудит усіх місць поточного зберігання даних учасників (травми/персональні дані).
- [ ] Перенести всі чутливі даних «Ашрам» на платформу із зашифрованим сховищем з нульовим розголошенням (наприклад, Cryptomator, Tresorit).
- [ ] Переконатися, що жодні дані учасників не зберігаються у вигляді відкритого тексту на комерційних хмарних дисках (Google Drive) або локальних незашифрованих ноутбуках.
- [ ] Впровадити суворий централізований менеджер паролів для всіх облікових записів організації.
- [ ] Впровадити багатофакторну автентифікацію (MFA) за допомогою фізичного ключа (YubiKey) або додатка-автентифікатора (TOTP) для всіх основних акаунтів (електронна пошта, банк, хостинг). MFA через SMS суворо заборонена.
- [ ] Протестувати процес відновлення резервних копій (Хмара -> Автономний SSD -> Новий ноутбук).
